## What must be built (the gaps, listed above, summarized)

1. **Ingest validation**: duration (≤2h) / size (≤20GB) ceiling with clear refusal reasons, on top of the existing `resolveIngestFile`/`probeVideo`. New `_inbox_footage`-style folder as a second configurable ingest root (distinct env var; the existing `CAPTURE_INGEST_DIR` stays as-is for the current flow so nothing regresses).
2. **Shortlist → whisper → moments pipeline**: call `extractSignals`+`rankHighlights` once at `3×N`/60s, slice each shortlisted window to a temp file, `transcribe()` each slice, offset word times back to source-file time, select final top N by score, snap boundaries to silence/scene-cut (never mid-word, using the word times as a hard constraint). Write `moments.json` as job evidence.
3. **Reusable loudness corrective-pass helper**: extract the measure→encode→re-measure→correct loop out of `LocalFfmpegCompositorProvider` into a shared function (used by both the existing compositor and the new clip renderer) — a small refactor, not a behavior change, to avoid duplicating that loop.
4. **Clip render**: for each final moment, cut the exact window, crop to 16:9 and to 9:16 (new center-weighted-crop filter graph, default; blurred-fill-pad as a config flag reusing the existing graph shape), burn captions from the window's word timestamps (new small `.ass` builder, separate from the narration one), apply loudness normalization (via the new shared helper).
5. **Clip QA**: compose `measureLoudness`/`loudnessProblems`, `bandStats`-based caption-visibility check, full-decode validation (`probeVideo` on the output), and `captionFitProblems` into one clip-scoped QA report. No script-match check (no reference script exists).
6. **Job wiring**: new `MediaJobKind = "SESSION_CLIP"`, following `domain/premiumRender.ts`'s exact start/execute/cancel/recover shape, with its own work root (`CLIPPER_WORK_DIR`, default `./.data/clipper-work`).
7. **New additive migration**: one new `MediaJobKind` enum value, one new model for the produced clip (two rows per moment, one per format) analogous to `ShortsRender` but FK'd to `HighlightCandidate`/`CaptureSession` instead of `ShortsScript`/`ShortsVoiceover` (those FKs don't apply — no script, no synthesized/recorded voiceover). Reuses `RenderReviewState` enum as-is.
8. **Studio UI**: "Clip a session" action on `/studio/captures` (same server-action pattern as `captures-actions.ts`), reusing the capture session the long file was attached to. Library page gets an additive second section/query for the new model, with reject/approve actions mirroring `reviewRender`/`approveRenderVersion`.
9. **New fixture**: a 10-minute synthetic clip, 5 planted events (reusing `action`/`quietAction` kinds for motion/audio bursts, a new rapid-scene-cut segment kind, and a new spoken-line segment using macOS `say` — already used elsewhere in this repo for synthetic voice — baked in at a known timestamp with known words) plus its ground-truth labels, extending `tests/helpers/fixtures.ts` (additive, existing fixtures untouched).

## Explicitly not reused (and why)

- `ShortsScript` / `ShortsVoiceover` / `ShortsRender` for clip output — those models assume a drafted script and a synthesized or recorded voiceover; a raw session clip has neither. Forcing placeholder rows through them would be a workaround, not reuse.
- `renderQa`/`narrationQa` wholesale — built around comparing speech to a known script; a raw session has no script to compare against. Their sub-pieces are reused; the whole function is not.
- The existing `LocalFfmpegCompositorProvider.render` crop graph for 9:16 — it only implements blurred-fill, not the center-weighted crop the spec wants as default. Left untouched; a new function handles clip cropping.
